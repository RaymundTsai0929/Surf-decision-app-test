RAG / 海象視覺原型 - 現況報告（問前）

1. 大致上做了甚麼
   - 既有 RAG 系統已可在 Streamlit 上運作：使用 `dataPDF` 資料夾的 PDF 建立 Chroma 向量庫，並用 Gemini（`gemini-3-flash-preview`）結合「即時海象文字預報」與檢索到的知識回答問題。
   - 已啟動並可在網頁端查看地圖/視覺工具，包含：
     - 「東港大鵬灣」分頁：目前使用 Google 地圖 iframe 作為底圖，並疊上 Windy 的 waves 圖層（半透明）。
     - 黃點「海上飄移示意」已被改成「疊在地圖畫面上」：使用透明 Canvas 直接覆蓋在同一個 iframe 容器內，點位以風＋浪＋海流的方向性向量合成後驅動。
   - 已補上中央氣象署開放資料授權碼流程：`CWA_AUTH_CODE` 已放入專案的 `.env`，程式端 `cwa_service.py` 已具備用於 CWA API 的基本架構，並保留原本近海預報函式，同時新增鄉鎮沿海逐三小時的函式草案 `get_coastal_timeseries()`（供後續改接）。

2. 有甚麼問題仍需要解決
   - 黃點的飄移數值目前仍「以 Open-Meteo 的風、浪、海流即時資料」為主（試作階段），尚未完成把飄移驅動改成「完全使用 CWA 鄉鎮沿海（F-D0047-095）」的資料。
   - 目前用 iframe 疊圖的方式，嚴格同步「拖曳移動後兩張圖自動對齊中心」在跨網域安全限制下仍做不到；現階段已先鎖定固定視角（中心/縮放）以確保對比一致。
   - CWA 鄉鎮沿海逐三小時資料在目前代碼裡尚未正式接到飄移動畫：需要確認東港對應的 `locationName` 與資料欄位（特別是風/浪/流是否有可直接轉成方向角與速度的數值欄位），再把後端解析結果傳給前端動畫。
   - RAG 部分目前仍是「近海海象文字預報」與 PDF 知識檢索的組合；若要更貼近東港鄉鎮沿海需求，需要把文字預報也改接 F-D0047-095 的東港資料（或至少把欄位映射到同一套顯示/摘要結構）。

3. 有什麼接下來建議
   - 第一步：先把飄移驅動資料源切換到 CWA 鄉鎮沿海（東港）。
     - 確認：東港在 F-D0047-095 的對應 locationName 字串是什麼。
     - 確認欄位：風向、浪向、流向是否提供可直接用於向量計算的角度/數值（或可由描述欄位安全映射成角度）。
     - 把 `get_coastal_timeseries()` 的回傳結構改成最終前端所需的：某個時間點的風/浪/流向量（u/v或speed/dir）。
   - 第二步：把「目前鎖定視角」升級成「根據選擇浪點自動導向座標」。
     - 當作 UI：選擇浪點（下拉）→ 後端或前端重載 Google+Windy 的 iframe URL（中心/zoom）確保對齊。
   - 第三步：RAG 的海象文本也改接到東港鄉鎮沿海逐三小時預報，讓回答更貼近使用者關注地點與時間尺度。
   - 第四步（進階）：如果未來要做到滑順且完全同步的雙層互動地圖，建議改用自建地圖底圖（Leaflet/MapLibre）+ Windy API 或替代資料源，避免跨網域 iframe 限制。
